# 随问桌宠

在阅读主聊天时独立追问。选区浮层和消息操作提供“问桌宠”，小窗拥有自己的滚动、草稿和答疑记录；收起不会取消解释或改变主聊天位置。

前端由 Akashic Web Chat 展示。普通 `companion` 插件发布 `/api/companion` HTTP 端点，复用入口登录守卫；解释通过可恢复读取的 HTTP 流返回，不依赖第二条 WebSocket。

## 数据与行为

- 每个主会话关联一个内部答疑 Session。Input/Output 通过 Ledger 公共 writer 保存，`visibility=internal`、`learning=excluded`。不向主会话追加消息，不触发主会话停止。
- 阅读引用、请求回执及主人明确设置的解释偏好通过 Ledger 的插件 owner 事务保存。原消息只从 Message Catalog 读取；裁切只影响模型窗口，不修改原文。
- 侧聊历史按主会话隔离；解释偏好共享。模型只接收当前引用、有限近期背景和本次答疑，不授予工具。
- 同请求 ID 幂等接纳。重连只读原请求；显式重新解释使用新 ID。插件重启遗留的在途请求显示中断，不自动重新付费调用模型。
- 收起小窗让解释继续；“停止”取消本次解释并保存已收到的内容。卸载插件保留 Ledger 消息和 owner 状态。
- 桌宠位置及未提交草稿属于浏览器本地界面状态。不会据“已解释”推断“主人已理解”。

## 验证入口

类型检查：`npm run typecheck`。依赖边界：`python scripts/plugin_boundary.py check --base <base>`。

浏览器验证应使用独立 `--state`，可用 `AKASHIC_PLUGIN_BUNDLE=companion-preview` 关闭 Computer。按真实安装链启动后，配置测试模型并检查：

1. 主聊天停在旧消息并保留草稿，选择文字后追问数轮；主聊天原文和阅读位置保持。
2. 收起、拖动、刷新及切换主会话，引用、各自答疑记录和解释偏好正确恢复。
3. 重连原请求不重复调用模型；停止、模型失败、后台重启后能保留事实并明确显示状态。
4. 用户点击“引用到主聊天”只添加草稿，不自动发送。
