# 模型用量

独立的只读插件，在「功能设置 → 模型用量」展示当前实例已入账的聊天模型调用。
默认发行组合启用；headless 和 minimal 不启用。停用此插件只撤下界面与查询路由，
Models 继续拥有调用账本。现有部署需要通过正式发行安装链取得新插件及新的 Models 合同。

## 第一版范围

- 过去 24 小时、7 天、30 天，按实际模型名称筛选。
- 输入、输出、缓存读取、缓存写入、推理 token 分别汇总，并显示各字段的已知调用数。
- 成功、失败、未结算、重试次数；平均首段响应、平均总耗时和端到端吞吐。
- 按 UTC 小时或自然日分桶的已知 token 走势，界面时间按设备时区显示。
- 每页最多 50 条调用明细，展开可看调用 ID、尝试序号和用量分项。

界面沿用宿主标题与纸面，首屏优先展示输入、输出、端到端吞吐和首段响应。
缩写 token 数字可用鼠标、触屏或键盘展开完整整数；缓存与推理分项按需展开。
输入与输出趋势分别使用刻度，悬停、点选或方向键可读取时段；未知用量以虚线标记，
不画成零值。明细在窄屏重排为摘要列表，翻页只重置列表内部位置，保留页面位置和焦点。
读取期间保留上次结果并标注正在更新，失败也不清除已有数据。

统计对象是物理尝试，重试分别计入；旧记录缺少尝试序号时保持未知。
首段计时沿现有 Models 定义，可能来自文本或思考，不声称是首个可见文字。
端到端吞吐是成功调用的已知输出 token 总和除以对应调用的总耗时，包含首段前等待。
缓存命中率只使用输入与缓存读取同时已知且输入大于零的调用，按 token 加权。
usage 的 `exact` 表示输入、输出已覆盖，不代表每个缓存或推理分项都已知。
缺失字段不按零计算；没有已知样本时显示「—」。推理和缓存分项不与总数再次相加。

仅覆盖 Models 调用账中已有的记录。Embedding、调用来源归因、费用估算和告警是后续范围。
不读取供应商账号的全局账单、剩余额度或其他实例的调用。

## 数据与接口

Models 发布 `models.usage-reports.v1`，消费方只依赖 `plugins.models.contract`。
`model_usage` 不持有数据库路径、连接、SQL、请求正文、响应正文或凭据。
`GET /api/dashboard/model-usage` 沿 UI 宿主的模块身份和 generation 校验，不另开监听器。
参数为带时区的 `start`、`end`，可选 `model`、不透明 `cursor`；范围为 `[start, end)`，最多 31 天。

Models 使用只读连接，在一次 SQLite 快照内计算总计、趋势和明细。
分页游标固定首次读取的行上界，排除随后追加的调用；已有调用后续结算仍可在新查询中显示。
每次查询最多运行 5 秒，超时明确报错；最多缓存 8 份公开结果，3 秒过期，随 Models 生命周期释放。
页面只在进入、筛选、翻页、刷新时查询，没有后台定时扫描。
不增加 schema、迁移、持久投影、保留期或自动删除，也不修改历史消息与模型设置。

## 验证

`python scripts/model_usage_scenario.py` 在隔离目录正式安装插件，使用真实 Models writer
制作合成调用账，经宿主 HTTP 验证字段覆盖、重试、吞吐、筛选、分页、模块身份和停用。
查询前后比较完整 SQLite dump，确认历史、schema 和设置不变。
`--port <端口>` 保留同一隔离实例供浏览器检查；先运行 `npm run build:dashboard` 和
`npm run build:web-plugins`。所有记录均为合成数据，不调用真实模型、不读取正式 workspace。
浏览器夹具额外包含大数、长型号和用量未知的模型。用
`npm run check:narrow-ui -- --url "http://127.0.0.1:<端口>/dashboard#model-usage" --page model-usage --browser <Chromium路径>`
验证响应式布局、键盘、分页与网络失败后的结果保留；截图写入私有输出目录。
