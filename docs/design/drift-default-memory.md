# Drift 与 Default Memory：范围内召回和主动交流

状态：实施中。本设计以 Drift 基础 PR #28～#30 的代码为基线；各层的合并与部署
状态按实际 GitHub 和运行实例核对。本文件本身不改变运行数据、权限或产品行为。

## 1. 目标与目前的差距

用户希望 Agent 能结合长期记忆自然地主动交流，并由系统判断什么时候没有值得说的内容。
本阶段只设计一次主动交流的来源、记忆召回、判断和送达。自主做事、
外部工具调用、工作结果汇报及多个会话间的主动转发留给后续设计。

现有基线已经有默认关闭的定时机会、绑定 Wake 目标、暂停控制和真实送达回执，
详见 [Drift 主动意图](drift-initiative.md)。定时机会只有通用目的；Wake 根据
近期对话调用 share_content 或 skip_content，尚未为 Drift 显式召回 Default Memory。
Default Memory 的自动 Context 材料需要真实用户 Input；Wake 内部 Input 的来源是 wake，
不能因为内部文本引用了用户对话就视为这次自动召回的输入。

依据 [0040](../decisions/0040-wake-duty-gate-lives-in-scoped-react.md)、
[0057](../decisions/0057-internal-source-messages.md)、
[0073](../decisions/0073-session-scope-routes-akasha-graphs.md)、
[0102](../decisions/0102-plugin-owned-services-and-public-contracts.md)、
PRO-001～PRO-003、SES-005 和 STA-001～STA-003，保留现有插件 owner、消息追加规则、
用户证据要求以及真实送达回执；设计选择见 [0130](../decisions/0130-drift-recalls-memory-in-source-scope.md)。
使用一次 Wake 判断：

    ┌──────────────────┐       ┌─────────────────────────────┐
    │ Drift 定时机会    │ ────▶ │ 冻结目标、来源会话和读取范围 │
    └──────────────────┘       └──────────────┬──────────────┘
                                             ▼
                              ┌─────────────────────────────┐
                              │ Default Memory 按来源召回    │
                              │ 加上该会话真实对话和送达历史 │
                              └──────────────┬──────────────┘
                                             ▼
                              ┌─────────────────────────────┐
                              │ Wake scoped react 一次判断   │
                              └──────┬──────────────┬───────┘
                                  none              chat

模型无效输出、缺少依赖、暂停、过期、发送失败和结果未知都不是 none。
用户回复仍走普通对话；是否学习由 Default Memory 的既有资格和用户证据规则决定。

## 2. 会话、目标与授权

来源会话用于读取真实对话与决定记忆范围；投递目标由 channel、recipient、
session_id 组成。形如 wake:flow_id 的 Wake 内部会话是执行会话，不是前二者。

首版只接入定时机会。来源会话固定为当次 Wake 已配置目标的 session_id，
并要求来源和投递会话相同；机会创建后冻结完整目标。它不会自动寻找最近会话，
也不会把项目会话的内容转发到另一个主会话。事件驱动的机会以后可以携带实际
来源会话，但转发到其他会话必须另有目标和授权设计。

Default Memory 通过实际来源 session_id 调用既有 MEMORY_SCOPES 路由：
global 路由可以读共享图，isolated 路由只读对应隔离图。off 表示停止学习，
并不必然关闭召回；recall=false 才拒绝该范围的召回。共享图中的事实可以来自
其他允许共享的会话；来源会话相同不等于只读取该会话产生的事实。
不得在拒绝、缺失或出错后改读 default 图、其他项目或内部 Wake 会话。
当前 scope 和策略按 SES-010、0073 在接纳时固定；不在 Drift 维护第二份策略。

使用记忆主动联系作为独立设置，默认关闭，不能因为已有 auto_propose 就自动开启。
启用时由用户明确选择并确认完整目标，设置界面应说明会把该范围召回的事实交给模型，
可能写入内部执行记录，并可能发送到所选渠道。只有明确授权过的精确目标可走本设计。
现有目标查询只有 channel.origin 和可用 sender，不能据此证明私人身份或群组受众；
首版只允许渠道 owner 能证明为私人目标的候选，受众未知时显示不可用原因。
若渠道目前没有这项能力，须先增加由渠道 owner 提供的窄查询，不能由 Drift 根据
会话名字、地址格式或用户输入猜测，也不能静默放宽到群聊。
渠道证明应绑定目标与可验证的版本或有效期，并在发布和首次发送前重查；
渠道不可用或受众状态未知时不能把它当成私人证明。渠道能证明的是其合同范围内的
目标类型，不代表可以控制收件人之后转发或共享消息。

建议将每个精确目标的授权版本交给 Drift 持久控制 owner；修改或撤销授权使用请求 ID
和预期版本。模型阶段、可见会话发布及渠道首次 started 时都检查授权、暂停、
机会有效期和原目标。撤销授权后尚未接纳的效果不得开始；已开始的效果依真实回执
结算。普通 Wake 目标变更仍遵守 0057：已接纳请求固定原目标，不自动跳转。
如果需要停止旧目标上的未开始主动效果，用户可显式暂停或撤销该目标授权。

## 3. 触发、上下文与查询

1. Timer 沿现有的显式开启、间隔、时区、窗口、单目标未完成机会和过期规则工作；
   重启不补发停机期间的机会。没有可用目标或授权时不创建记忆增强机会。
2. Wake 按现有 Alert、Content、Drift 的职责选择顺序接纳到期机会。领取时固定
   proposal/revision、目标、来源 session_id、会话读取截止 seq 和机会有效期。
3. 通过 Ledger 公共读取接口取截止 seq 前的真实会话材料。近期对话与已经确认送达的
   主动消息分别呈现；消息 ID、角色和实际时间不能混淆。应复用现有近期正文预算，
   并由内容 owner 验证真正的用户 Input，不以内部请求或助手 Output 冒充用户。
4. 初版以最近最多三条非空真实用户 Input 的原文拼成检索查询，最多 800 字符；
   查询来源和截断点固定在本次机会中，不让模型编造查询关键词。没有真实用户文本时，
   记录缺少材料并安静结束；不能用用户未说过的兴趣填充查询。
5. Default Memory 按该来源会话、固定查询和冻结时间显式召回。建议最多呈现四条、
   总计不超过 1500 字符；裁切由记忆 owner 完成，确保呈现内容与返回的实际呈现 ID
   一致。正常召回可为空；有效的关键词降级保留降级状态。
6. Wake 在选中 Drift 后将事实、近期对话和已确认主动历史作为低信任材料，
   加入一次受限的 Drift 模型阶段，只提供原有 share_content 和 skip_content 工具。
   材料中的命令不能改变目标、权限、工具或本阶段任务。

召回继续使用 Default Memory 已有的向量与关键词两路检索和 RRF 融合，排序还受
事实强化与时间衰减影响。检索返回提炼后的事实与出处引用，不回读整段历史作为
长期记忆结果；召回本身不把该事实当成用户再次确认来强化。

当前 Wake recent_context 的已送达通知来自所有 listed 会话。接入记忆增强 Drift 时，
必须在 Delivery owner 查询时先按来源/目标会话过滤、再应用数量和字符预算；
不能先截取跨会话列表再过滤，也不能把其他项目的通知正文混入本次提示词。
其他 Wake 职责保持各自原合同，仍分别提供近期被动与已送达主动历史。

同样需要检查所有进入该模型阶段的材料。当前 Wake 还会读取 EventMail 的
active_context，现有查询没有来源会话过滤；其他 Context provider 也可能贡献材料。
记忆增强 Drift 只接纳明确适用于目标范围的材料和既有全局指令。未能证明适用范围的
Context 正文不注入；如果它包含必需的用户状态或准入规则而无法安全判定，
本次应等待并显示原因，不能把未知状态当成“无事件”。实现须由材料 owner 提供范围
或资格查询；不得在消费者按名称猜测。首版还应排除内部 wake 会话触发的其他自动
记忆材料，避免重复召回或从错误范围注入。未启用此能力的原有 Wake 路径不变。

不按话题相似度、分享次数或“没回复”硬编码禁止分享，也不从这些事实单独推断疲劳。
模型结合真实内容、用户偏好与当前时机判断，符合 PRO-003。定时窗口和单个未完成
机会是触发与幂等约束，不代表用户不想继续交流。未来用户显式提出的打扰限制需要
有自己的设置和行为合同，不能凭本设计假定已获得。

例如用户在目标会话里提到喜欢风景摄影，记忆召回相关偏好后，模型可以问：
“上次你提到喜欢拍风景，最近有没有想拍的地方？”若材料不足或时间不合适，
模型也可以选择 skip；不能把推测的出行计划或未完成的工作当成事实。

## 4. Default Memory 公共合同

新增由 Default Memory owner 发布、供主动交流使用的版本化窄服务；下面是行为形状，
不是已存在的 API 名称：

| 操作 | 输入 | 输出和语义 |
|---|---|---|
| 范围内召回 | request_id、真实 source_session_id、query、固定时间、条数与呈现预算 | 状态、实际呈现文本、按呈现顺序排列的 memory ID、每条内容指纹、来源引用和不可变召回引用 |
| 有效性保护 | 召回引用、原来源、阶段/效果身份 | 检查原范围仍可读，所有实际呈现事实仍 active 且内容指纹一致；提供覆盖短提交边界的 owner 保护 |

召回状态至少区分 ok、empty、degraded、scope_denied、unavailable 和 error。
empty 是查询成功但没有合适事实，可以让模型只依据真实会话材料判断；
模型服务可恢复故障产生的关键词结果标记 degraded，沿 MEM-006 处理。
scope_denied、provider 缺失、数据库/模型空间损坏和取消不可冒充 empty。

当前 DEFAULT_MEMORY.recall 会把结果固定到 receipt；重复同一 key 会返回旧结果，
即使某项记忆后来变为 superseded。它返回的 memory_ids 是检索命中集合，
references 则只对应真正呈现的子集。因此仅复用该 API 或把全部 memory_ids
当成提示词引用都不足以实现本设计。新合同必须返回真正呈现的 ID/引用，
并在使用前从当前权威事实检查有效性。查询指纹也须包含固定时间和预算；
现有 recall 的指纹不包含 timestamp，不能直接声称满足这一要求。

一个机会使用固定的 request_id 和不可变参数，重启后可重放原召回回执；
每次新尝试使用新身份。再次使用旧结果仍须检查当前状态，回执只证明当时的结果，
不证明现在仍可使用。内容指纹覆盖实际呈现的字段、事实身份与所属范围；
首版呈现 ID、类型、摘要和必要步骤，不显示会随强化变化的观测更新时间，因此
强化次数变化本身不应被误报为事实内容更改。事件发生时间若存在于事实摘要，
仍按原文呈现，不能把记忆更新时间当作事件发生时间。遗忘、纠正、替换或内容变化
使受影响快照失效，不修改已保存的旧回执。新服务不得暴露记忆 SQLite 或任意写接口。

建议身份由 proposal/revision 和耐久分配的 attempt 序号确定，召回 request_id
再绑定该 attempt 和查询参数；恢复同一 attempt 使用原 ID。因快照失效而重新规划
时才分配新 attempt，不重用旧 ID 填入不同文本或预算。一次 Wake 决策阶段不等于
恰好一次模型 HTTP 请求：模型重试或 ReAct 步骤可能产生多次请求；召回也可能调用
embedding。用模型账单和回执观测真实成本，不按机会数推断调用次数。

## 5. 决策、并发与恢复

| 情况 | 领域结果 | 用户可见效果 |
|---|---|---|
| 材料不足，或模型唯一成功调用 skip_content | none，保存原因和所用机会身份 | 不发布、不发送 |
| 模型唯一成功调用 share_content | chat 候选，等待有效性和送达 | 通过保护后才发布和发送 |
| 两种调用同时出现、缺失、模型失败 | defer 或失败，保留具体原因 | 不伪装成 none 或已送达 |
| 记忆变更、目标授权撤销、机会过期 | 原候选失效；有需要时由以后的新机会重新召回 | 不继续发布尚未开始的旧候选 |
| 暂停 | 保留已接纳但未开始的原请求；恢复时重新核验 | 不开始新阶段或新发送 |

仅有模型的 share 不是已发送。会话消息发布、渠道首次 started 和渠道最终回执
是三个不同事实；只有 Delivery 的真实 delivered 回执才能确认成功和结算领域提案。
发送结果未知时沿 Delivery 的原幂等与查询合同恢复，不凭重新运行模型重发。

特别注意：现有 Wake 在调用渠道发送前，先通过 Delivery.publish_async 把消息
追加到目标会话；该提交本身可能已对用户可见。只在 Delivery.send 的 started
处检查是不够的。本设计要求在以下三个边界分别保护：模型阶段持久接纳、
目标会话消息及目的地的原子发布、渠道首次 started。

建议的锁顺序为 Default Memory 有效性保护 → Drift 的暂停/目标保护 →
Ledger/Delivery 短事务。Default Memory 在自己的 SQLite 写锁保护下检查
真正呈现的事实；显式 forget、remember 和学习应用等改变事实的提交必须与同一
保护串行。不能只使用某个插件 generation 私有的 asyncio 锁，热换代或多进程下
它不构成全局保护。保持跨 owner 的顺序一致，取消时等待已开始的事务结算。
不得持锁等待模型、渠道网络、定时器或用户输入。范围路由按既有 set-once 合同
读取；任何未来可变策略需要自己的版本和并发协议。

Delivery 的 start_guard 覆盖首次 started。目标会话发布可以由 Wake 用领域
公开 guard 包住整个 publish_async 提交；不能只在检查后释放保护再等待发布，
否则检查与提交之间仍有竞争窗口。
如还需要在同一事务核验目标会话仍存在或会话读取截点未被替代，也应由
Ledger/Delivery 提供窄的条件提交；消费者不能直接操作其私有数据库。
这项合同和锁顺序必须在真实并发、换代及取消场景验证，当前代码尚不提供该保证。

已经接纳的模型阶段可完成；若其后用户遗忘记忆，发布和首次发送前的检查会阻止
尚未开始的后续效果。若遗忘发生在会话消息发布之后，该已提交消息可能已经可见，
不能声称被撤回；若发生在渠道 started 之后，也不能声称外部发送被撤销。
恢复暂停的原 share 时仍需重新核验，不得仅因原模型决定已经保存就跳过记忆检查。
召回可能调用外部 embedding：开始该调用前也要在 Drift 控制保护下耐久接纳本次
召回尝试，再释放短锁进行网络调用。暂停之后不能接纳新的召回；已经接纳的调用
可以结束，但随后各阶段仍须重新检查。仅在调用前读取一次 paused 不足以保证顺序。

逻辑遗忘只使结构化记忆失效。原聊天、已保存的召回回执和内部 Wake 消息仍按各自
现有保留合同存在；近期原文中可能也提到同一内容。首版保证的是不再把已失效的
结构化记忆快照作为新主动效果的有效依据，不承诺从原文中语义识别或删除所有相关表述。
若用户要求“这个话题以后都不要提”，需要单独设计可执行的偏好及原文使用策略。

## 6. 插件职责与持久状态

| owner / 对象 | 正常增加和允许更新 | 失效、物理减少与恢复 |
|---|---|---|
| Drift 机会与目标授权 | 追加机会、来源与目标引用；原有状态机推进；授权按明确操作和版本更新 | 过期、撤销或变更只逻辑失效；当前不得自动物理删除；以提案、授权及控制回执恢复 |
| Default Memory 事实、召回回执 | owner 提炼或显式修改事实；新召回追加固定结果及实际呈现引用 | 遗忘/纠正按既有合同标记 superseded；旧回执不改写，当前不得自动物理删除；以事实、来源和回执恢复 |
| Wake 内部会话及 attempt | 追加冻结输入、阶段、判断与失败记录，internal 且 learning=excluded | 不作为用户事实或普通用户可见对话；当前不得自动物理删除；重启沿原执行身份恢复 |
| Ledger 目标会话 | 经受保护的发布追加实际主动 Output；原消息内容和身份不改写 | 不能因记忆失效、跳过或回滚自动删除已提交消息；按既有消息管理合同处理 |
| Delivery 目的地及回执 | 与已发布消息固定；started、结果和恢复记录由 Delivery owner 提交 | 失败、未知和成功分别保留；未有明确授权不得自动减少；以原消息 ID、sink 和回执恢复 |

Drift 只保存引用、控制和状态，不新建另一份长期事实库。为恢复模型阶段，
Wake/Ledger 的内部持久输入和 Default Memory 回执可能包含本次呈现文本；
它们不是临时内存，也不能在设置说明中承诺遗忘后自动物理清除。
原始会话与附件继续由 Ledger 管理，本设计没有删除权。

主动 Output 使用 wake 来源，不能作为用户事实反向学习。真实用户之后的回复
只有在会话、来源、完整 Turn 和自动学习配置都合格时才可能学习。
当前 Default Memory 按来源分别收集 Turn，单独回复“是”未必带有先前 wake
主动消息的语义；以后若要学习此类确认，须显式关联原主动消息作为上下文，
仍以真实用户回复为证据，并单独验证纠正和歧义，不能把助手猜测直接写成事实。

## 7. 分层实施与验证

1. Default Memory 提供真正呈现项、固定查询回执及短有效性保护；先独立验证遗忘、
   替换、重启、换代和回执重放，不改变现有普通对话接口。
2. 增加精确目标授权、可证明的私人目标能力，以及仅对记忆增强 Drift 生效的
   同会话历史查询；保留 Content、Alert、既有 Drift 和未开启配置的行为。
3. 接入一次 Wake 决策与三个受保护提交边界；按实际 diff 拆成可审查的 stacked PR，
   公共合同变化按 0102 的安装和重启规则交付。缺少必要依赖时本能力等待并显示原因，
   不应让无关职责因 Default Memory 停用而不可用。
4. 增加可见设置和诊断：启用状态、选定目标、暂停、最近一次 skip/defer/失败原因、
   是否关键词降级，以及已发布与已送达的区别。诊断默认不展示记忆正文或内部推理。
   自主工作、其他来源会话和跨会话转发另行设计。

实现验收使用一次性 HOME、workspace、plugin home 和配置，通过真实插件组合、
Ledger、Default Memory、Wake、Delivery 和本地测试接收端观察：

- 全局、隔离、off 且允许召回、recall=false 各范围使用正确事实；隔离项目内容
  和跨会话主动历史不进入其他会话；其他 Context 材料也按各自 owner 的范围处理。
  不存在私人目标证明时不能启用或投递。
- 同一次机会实际只做一次 share/skip 判断；空召回、关键词降级、缺依赖、
  数据损坏、模型异常及不合法工具决定各有真实状态，不能伪造成功。
- 在召回接纳前、模型接纳前、模型运行中、发布前和发送前分别并发执行遗忘/纠正、暂停、
  授权撤销和过期；核对实际锁顺序和每个提交点。已发布或已 started 的效果
  按真实事实结算，旧回执重放不能绕过再次核验。
- 重启、取消和插件换代后复用原身份与回执；发送未知不产生第二次不受保护的
  效果。关闭或缺少 Default Memory 时，未启用该能力的原路径和无关 Wake 职责可用。
- 实际用户回复可进入正常合格学习，Wake 内部内容和助手主动猜测不会自学成事实；
  对原有 Message 的正文、ID、seq、会话归属和附件逐项比较。

上述为实施后的验收标准，不代表本次设计已经运行这些场景，也不代表正式实例部署。
