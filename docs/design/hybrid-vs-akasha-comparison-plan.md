# Hybrid 与完整 Akasha：双组对比计划

- 日期：2026-09-23。
- 状态：已获运行授权，开始真实数据实验；LongMemEval 主实验固定为 provided-history。LoCoMo 下载与 Sol 登录状态在启动检查中核验。
- 本轮范围：只比较 H（向量＋BM25）与 F（完整 Akasha）。其他消融、PersonaMem 扩展不自动包含在本轮。
- 目的：判断完整 Akasha 相比常规混合检索是否在证据覆盖、回答质量和资源消耗上更有价值。
- 结论边界：F 包含情景关联、时序/上下文处理、候选选择和排序等差异。H/F 对比不能将全部收益单独归因于图扩散。
- 参考基线：日常源码 `4cc5cbe31523d6d3fe8c59f07a53c97c729f57cb`；旧实验提交 `3bfb002b7ff79bb8a66e20a3c9cffe6e4eb4cae9`。实施时记录实际源码、插件制品和配置摘要，不假设 worktree HEAD 未变。

## 1. 两组的精确定义

| 项目 | H：Hybrid | F：Full Akasha |
|---|---|---|
| 原始历史 | 数据集给定的完整历史（provided-history） | 相同 |
| 历史单元 | 固定的历史轮/片段及其原始消息映射 | 相同，不能以 hub 作为更大的评分单元 |
| 向量 | 同模型、同维度、同归一化的缓存向量 | 相同 |
| 向量得分 | 查询向量与该轮 user/assistant 向量的最大余弦相似度 | 保留当前精确召回与种子计算 |
| 稀疏得分 | 相同分词与历史范围的 BM25 | 保留当前词法证据计算 |
| 组合方式 | 等权 RRF，保留融合后的原生排名 | 保留完整 Akasha 的精确召回、情景补全及原生排名 |
| 情景图、burst 派生处理 | 不使用 | 保留当前实现 |
| 显式遗忘/可见范围 | 相同过滤规则 | 相同 |
| 最终证据预算和渲染 | 统一 | 统一 |

H 的默认参数：BM25 k1=1.2、b=0.75；向量与 BM25 各最多取前 100 个有效候选；RRF 常数 k=60，排名从 1 开始，缺席某一路贡献为 0；分数相同按稳定证据 ID 排序。只有非空且有效的候选进入各路排名，不能让全零 BM25 结果伪造词法命中。

可以复用当前 FeaturePool 的原始 dense/BM25 评分，不能误用已经结合 burst、context 或图状态的得分。参见 [features.py](/Users/namei/idea/akashic/plugins/akasha/domain/features.py:124)。参数如需调整，只能使用开发集，在读取本轮保留集结果前冻结。

F 使用固定版本生产算法，不根据评测题目人工加边、替换召回目标、增加召回次数或改变学习顺序。原生排序差异属于本次策略比较；不强行给两组重排成同一种结果而声称仍是原始 Full。

## 2. 数据计划

### LongMemEval cleaned-S

- 沿用已经固定的 30 题开发集和 100 题保留集，不能重新抽一份更有利的题。
- 保留集包含 20 道 multi-session；无答案题按 `_abs` 单独识别，共 14 道，不能只用 question_type 统计。
- 报告全部题及跨会话、更新、时间、拒答等分组，不将分组中最好的成绩冒充整体成绩。

### LoCoMo

- 固定数据 commit/hash，按 conversation 划分：2 段开发、8 段保留，随机种子 `20260923`。
- 在保留对话中按类别和对话尽量均衡抽取：60 道 multi-hop、20 道 single-hop、20 道 temporal、20 道 adversarial，目标 120 题。
- 某类不足则全取，记录实际数量，不更换对话或依据实验结果补选题目。
- 保留原说话人、时间和 dia_id；两位说话人不能直接被误解释为个人用户和助手。适配方法在 manifest 中固定。
- 只使用原始对话，不额外注入官方 observation、summary、evidence 标签或标准答案。

目标正式题数 N=220；LoCoMo 实际题数不足时按真实 N 计算。两个数据集独立统计，不拼成一个“综合 benchmark 分数”。

现有划分：[splits](/Users/namei/.local/share/akashic-eval/experiments/phase1-sol-max-20260919-v3/splits)。LoCoMo 尚需新增适配与划分。

## 3. 公平条件

1. 固定历史切分、内容、speaker、原始时间、消息映射、分词器、embedding 模型和维度。主实验按数据集给定的完整历史评测；问题时间不改写，查询和标准答案不写入记忆。严格按问题时间截断仅作为独立补充协议，不与主实验混报。
2. H 与 F 的质量比较允许复用同一份受校验历史向量，但不能复用另一组的 QA、召回记录或答案。
3. H 构建词法与向量索引，不运行情景图学习。旧实验里所有组都建图的流程不能直接拿来比较构建时间、RSS 或存储成本。
4. 质量主实验统一渲染模板，只包含原始证据 ID、说话人、时间和正文，隐藏组名、lane 及算法解释。
5. 主预算为 12,000 字符，包含模板标记；统一去重、展开、超限跳过规则，不以 K 相同替代实际预算一致。记录实际字符、token、证据数。
6. 查询与回答不写回记忆，原图/索引的逻辑状态前后保持一致。每次查询还原临时状态，不让先运行的题改变后运行的题。
7. 回答模型固定为上一轮的 `gpt-5.6-sol / max`，embedding 为 `text-embedding-v4 / 1024`；验证实际服务身份，不静默更换配置。
8. 回答提示词、输出上限 4,096、超时 300 秒相同。固定 reader 只回答一次，不允许二次检索、Shell、SQL、网络或读取完整历史。
9. H/F 按题交替先后；重复轮次轮换。先单 worker，不把模型服务竞争引入主测量。
10. 只能在开发集调整实现；正式结果不理想也要保留，不能挑题、挑最好一次或删掉超时。

字符预算用于保持上一轮可比性，不声称字符数等于 token 数。实际 token 差异必须与质量结果一起报告；以后需要严格 token 预算时另立协议版本。

## 4. 两层实验

### 层 A：只测检索

相同问题分别调用 H/F，保存排序前后候选、实际呈现证据和耗时，不启动回答模型。

有证据标签时，设 G 为标注证据集合、P 为预算内呈现集合：

- 主要检索指标：PresentedRecall@B = |G∩P| / |G|，按题宏平均。
- 完整标注证据覆盖率：G⊆P 的题目比例。它描述官方标注全集，并不假定标注穷尽所有可能答案依据。
- 配对新增和丢失：F 新找回哪些证据，H 找到但 F 丢掉哪些证据；同时报告净变化。
- 辅助 Recall@5/@10：统一原始证据粒度后计算，不能按 hub 和消息混算。
- 无证据标签与无答案题不计算 Recall，不将缺标签自动记成召回成功。

延迟分别计入查询 embedding、检索/图计算和渲染。相同输入的 query embedding 可作为质量实验共享常量；性能报告分别给出含 embedding 与不含 embedding 的时间，避免将缓存命中与真实请求混比。

可在冻结的 3,000/6,000/12,000 字符预算上画纯检索曲线，主结果固定为 12,000，不事后挑最有利预算。

### 层 B：检索＋固定模型回答

将 H/F 各自的证据交给同一 reader。两组每题各生成 3 次，保存全部答案与错误。

- LongMemEval：固定官方分题型 rubric 和主裁判，报告语义正确率。
- LoCoMo：固定官方答案 F1；另报开发阶段冻结规则的严格语义正确率和无答案题正确拒答率。官方分数与自定义分数明确分开。
- 裁判匿名盲评，不得看到 H/F 标签。裁判失败只重新判同一答案，不重新生成答案。
- 超时、执行失败进入端到端失败统计及任务成功率分母；裁判 pending 未解决前不发布最终质量结论。
- 多次生成先按同一题汇总，不能把 3N 当成独立问题数，不能用 best-of-3。
- 按题配对比较；LoCoMo 按 conversation 聚类计算 95% 区间，同时报告只有 8 个保留对话带来的不确定性。

固定 reader 试验中的工具调用预算为零，因此本轮不能宣称减少 Agent 工具调用次数。那需要后续相同 ReAct 工具预算的独立集成实验。

## 5. 执行批次与预算

| 批次 | 内容 | 数量 |
|---|---|---|
| 0 | 适配、索引、证据映射、预算和判分 fixture | 本地验证，不运行付费回答 |
| 1 | 开发 pilot：12 道 LongMemEval＋12 道 LoCoMo，H/F 各一次 | 目标 48 次回答生成 |
| 2 | 冻结后的纯检索，全部保留题 H/F | 主预算下目标 440 次检索 |
| 3 | 正式 reader，全部保留题 H/F，各 3 次 | N=220 时为 1,320 次回答生成 |

批次 1 统计真实用量、耗时与错误，再计算批次 3 的费用和预计运行时间。回答生成次数不是总 API 次数，历史/查询 embedding、裁判和预先规定的传输重试另计。本计划不预估未测的价格或承诺固定工期。

批次 2 的结果不能用来调参后继续把同一份数据当全新保留集；若发现实现错误，登记无效 run 和新实验版本，旧结果保留，报告测试集暴露情况。

实施复用现有 [memory_ablation.py](/Users/namei/idea/akashic-worktrees/benchmark-readiness/eval/memory_ablation.py) 中的数据、隔离与记录逻辑，但需要新增 hybrid、LoCoMo、固定 reader 和独立基础索引准备。之前的 none/dense/full 结果不能冒充本轮 H/F 结果。

## 6. 结果判定

| 观察 | 可以得出的结论 |
|---|---|
| F 找到更多证据且回答更好 | 完整 Akasha 在本数据与预算下有质量收益；不能仅凭双组对比归因于图 |
| F 证据更多但回答不变 | 检索覆盖提高，回答价值尚未证明 |
| F 回答更好但慢很多 | 报告质量与延迟取舍，由个人 Agent 的使用需求决定是否采用 |
| F 成本更低、质量点估计接近 | 报告观察结果；未检出差异不等于已经证明质量相同 |
| F 简单题/拒答退化 | 明确报告退化，不能只展示多跳题收益 |
| 差值区间跨零或跨可接受范围 | 尚未证明稳定优势，不为获得显著结果反复追加样本 |

若要宣称“质量不下降而成本降低”，需要在看正式结果前登记非劣界限并按区间检验。没有该前提时只报告两组质量与成本的实际差异，不使用等效或不下降结论。
