## 1. 要回答的问题

H1：在固定证据预算下，完整 Akasha 相比向量＋BM25 能否找回更多跨会话问题的标注证据？

H2：新增证据能否提高同一回答模型的答案质量，而不只是增加上下文？

H3：收益是否依赖情景关联机制；简单问题、时间题和无答案问题是否出现退化？

检索层和回答层分开测试。一次固定查询的检索先不启动 ReAct 多轮搜索，防止模型改写问题、重试工具等因素掩盖记忆模块本身的表现。真实 Agent 多步执行另作集成检查。

### 2.2 次级扩展

PersonaMem v1 沿用已有 21 题开发集和 70 题保留集，测试偏好利用与更新。已有划分无 persona_id / shared_context_id 交叉。该部分在主实验完成后单独执行、单独报告；不用于直接证明图传播机制。

本轮不同时升级到 LongMemEval-V2 或 PersonaMem-v2，也不把 MuSiQue / HotpotQA 改造成主实验。它们分别涉及执行经验、隐含偏好或跨文档问答，适合后续独立实验，不能与当前子集混算。

### 2.3 输入适配

- 只导入查询时点之前的原始历史，保留原会话、时间、说话人及消息 ID 映射。
- LongMemEval 的标准答案、has_answer、answer_session_ids 只供评分使用，不能成为模型或图学习输入。
- LoCoMo 两个说话人不是天然的 user/assistant。需要显式记录说话人保真映射；不能把另一人的偏好误记成当前用户，也不能用 QA 答案补写助手回复。
- LoCoMo 的生成 observation、session_summary 和标注 event_summary 默认不作为记忆输入。若以后使用，单列实验组并计入构建成本。
- 适配后的原始证据原子须能映射回官方 message/dia_id；各组使用同一原子划分。图节点、hub 数不能冒充证据条数。

## 3. 对照组

| 组别 | 定义 | 检索层 | 正式固定 reader 问答 |
|---|---|---|---|
| D：Dense | 同一 embedding 空间的纯向量排序，遵守相同遗忘与可见性规则 | 全部 | 开发阶段及参考结果；不作为唯一强基线 |
| H：Hybrid | 同一证据单元的向量＋BM25，使用固定 RRF 融合 | 全部 | 主要对照组 |
| F：Full | 当前完整 Akasha 的精确召回与情景补全 | 全部 | 主要实验组 |
| C：NoCompletion | 同一 Akasha 快照、输入与配置，仅关闭补全输出 | 全部 | 默认不跑，用于机制诊断 |
| T：TemporalOnly | 同一快照与初始证据，在所有相关扩散路径中仅保留时间关系 | 有效实现后全部 | 默认不跑，用于结构归因 |

Hybrid 默认冻结为两路各取前 100 个候选、等权 RRF、常数 k=60，分词规则与空间身份记录在 manifest。开发集如需改变，必须在首次读取保留集结果之前完成并冻结；不能将混合基线调成明显不合理配置。若 Hybrid 在开发集显著弱于 Dense，先审计实现，不能据此提前宣布图有效。

C 组的候选可能明显更少，只能说明补全输出贡献，不能替代同预算 Hybrid。当前 include_completion=False 仍执行前面的 residual_push，因此它不是无图计算的延迟基线。

T 组要求所有相关图扩散实际使用时间关系视图，不能仅关闭最外层 diffusion 而保留内部 basin diffusion。其余文本、向量、初始种子、时钟与算法参数不变；合法性检查通过后才纳入报告。若暂未完成，应记 NOT RUN，不能用 C 冒充 T。

另选开发集的小型无记忆检查，用于识别常识、选项或模型先验即可回答的题。它不参与主比较，也不增加一条覆盖所有保留题的模型运行链。

## 4. 统一证据预算

- 主预算 B：12,000 个字符，保持上一轮口径，计入统一标题、时间与来源标记；同时记录实际输入 token。
- 统一渲染模板：原始证据 ID、说话人、时间和正文。受控 reader 实验不展示组名、dense/completion 标签或算法专属解释。
- 检索指标主要在最终预算内实际呈现的证据上计算，原始候选指标作为诊断另报。
- 各组具有相同预算上限，不为凑满预算插入无关占位文字。实际字符数、token 和证据数一起报告。
- 辅助 Recall@5、Recall@10 使用统一原始证据单位；固定统一去重/展开规则，不能将一个 hub 与一条消息直接比较。
- Akasha 内部 limit 是通道相关参数，不能直接视为最终总 K；完整输出可能包含精确候选和补全候选的合并。以实际交付清单为准。
- 额外预算曲线只在预先登记的 B=3,000 / 6,000 / 12,000 字符上做纯检索测试，主成绩固定为 B=12,000，避免事后挑最有利预算。

## 5. 指标和判分

### 5.1 检索主指标

对于有非空证据标签的题，设 G 为标注证据 ID 集合，P 为预算内呈现的原始证据 ID 集合：

- PresentedRecall@B = |G∩P| / |G|，按题目宏平均。
- 完整标注证据覆盖率 = G⊆P 的题目比例。它是“标注全集覆盖”，不承诺每个数据集的全部标签均为逻辑必需或穷尽证据。
- 配对新增命中：F 命中、H 未命中的标注目标；同时报告 H 命中、F 丢失的部分及净变化。
- 第一跳与后续证据可人工标注在开发机制样例中；公开数据若没有明确路径，不把人为假设当官方标签。

没有证据标注的题不计算 Recall。未被标注的其他召回不自动判为错误，因为公开 gold 可能不穷尽所有有效证据。

### 5.2 回答主指标

- LongMemEval：使用固定版本官方分题型 rubric，报告全部 100 题及各题型的语义正确率。裁判模型与官方论文配置不同时明确注明，不直接声称榜单同口径。
- LoCoMo：保留固定官方答案 F1 作为可比较分数，同时对跨会话问题报告预先定义的严格语义正确率。adversarial 的正确拒答单独统计。
- PersonaMem v1 次级实验：要求单一合法选项，严格解析后按标签评分；不能使用宽松词汇重叠猜测标签。
- 超时、运行失败和无有效答案保留在任务成功率分母。裁判失败另列 pending，重新判同一答案；未解决前不发布最终质量结论，不重新生成到答对为止。

裁判看问题、标准答案、必要的官方题型条件及匿名回答，不看实验组、图来源或研究假设。LoCoMo 的严格语义判分须先在开发题上审计，引用和证据支持程度与答案正确性分别记录，不凭句子包含关键词判正确。

### 5.3 关联错误与资源指标

- 无答案题正确拒答率；简单题和时间题的退化情况。
- 对预先标注的反例，分别记录错误目标入选率与错误关系被用于回答的比例；它们不能混成一个指标。
- embedding、记忆查询、排序/渲染、模型、整次问答分别计时；报告中位数和 P95、样本数与超时比例。
- 输入 token、缓存输入、输出 token、工具次数、新查询 embedding 用量分开记录。缺失用量标 unknown。
- 历史索引构建、后台学习、日常查询成本分开；模型裁判成本另列。若所有组共用图准备，不能据此比较各自最小启动或存储成本。
- F/C 运行的图传播次数和耗时不自动等于收益；需要与实际证据和回答相联系。

## 6. 模型、状态与重复规则

- 回答与主裁判沿用上一轮 `gpt-5.6-sol / max`，embedding 沿用 `text-embedding-v4 / 1024`；记录 provider 实际返回的模型与空间身份。不可用时明确报告，不静默换模型。
- 固定 reader 每次只接收当前问题和预算内证据，单次回答不开放 Shell、SQL、网络或二次记忆查询。输出上限 4,096，问答超时 300 秒；参数在开发 pilot 后冻结。
- 正式主比较 H/F 每题各生成 3 次；固定支持的采样参数。即使 temperature=0，也不假设服务完全确定。
- 三次分别报告，再给每题平均结果；不能将 3N 当成 3N 个独立问题或采用 best-of-3 冒充单次正确率。
- 历史学习不读取问题、gold 或未来内容。每次 QA 在只读图状态上运行，测试答案不写回；临时查询状态恢复后逻辑 hash 不变。
- 历史向量可以共用受校验缓存；旧 QA、召回结果和回答不能复制进新实验。各组固定图版本、截止时间与可见历史。
- 各题 H/F 顺序交替，重复轮次轮换；先单 worker 减少服务竞争。扩大并发需作为明确的新测量条件。

## 7. 实施与运行顺序

### 阶段 0：实现测量接线，全部使用本地 fixture

1. 新建隔离评测 worktree，确认其实际基线；移植上一轮实验适配时只带必要变更。
2. 新增 LoCoMo adapter、Hybrid、C/T 消融与统一 renderer。
3. 验证 source ID、说话人、时间、候选数量、实际模型材料和 gold 隔离。
4. 用有已知关联链的小图检查图干预，并用原始对话自动构图检查实际学习路径。手工构图单测不能替代公开数据效果测试。
5. 对官方评分做正例、错误答案、拒答、空输出和解析失败 fixture，确认失败没有被排除分母。

产物：适配与边界测试结果、协议 manifest 草稿。任何付费正式实验之前先过这些检查。

### 阶段 1：开发 pilot

- 使用 LongMemEval 开发题 12 道，LoCoMo 开发对话中预先选 12 道，共目标 24 道。
- D/H/F 三组各运行一次固定 reader：最多 72 次回答生成，不等于总 API 请求数。
- 记录模型用量、构建时间、检索时间与裁判成本，检查判分分歧并修复适配错误。
- 用全部 30 道 LongMemEval 开发题和 LoCoMo 开发对话题做纯检索校准，最终冻结配置与清单。

产物：可重复的开发报告和正式运行预算。不能把这阶段反复调参后的分数写成保留集成绩。

### 阶段 2：冻结后的保留集检索

- LongMemEval 100 题＋LoCoMo 目标 120 题。
- D/H/F/C/T 五组查询；无证据题仍运行，但单列评分。
- 先保存候选和呈现证据，再计算指标。结果不能用于回头修改本次实现；发现实现缺陷则明确宣布本次无效并创建新实验版本。
- 同时报告全部题和预先定义的跨会话/多跳子集；“直接检索困难”按冻结基线排名定义，作为诊断分组，不取代全部结果。

产物：证据覆盖、来源贡献、图消融、查询耗时与回归样例。

### 阶段 3：主要问答对照

- 同一批保留题，H 与 F 各生成 3 次。
- 实际 N=220 时，共 220×2×3=1,320 次回答生成；LoCoMo 取样不足时按实际 N×6。裁判、历史 embedding 和重试另计。
- 两个数据集分别报告，不把不同评分拼成一个“综合准确率”。
- 按题目配对比较；LoCoMo 按 conversation 聚类计算不确定性，不把 8 个保留对话的全部题视作互相独立。
- 记录 95% 置信区间与有效聚类数。公开样本特别是 LoCoMo 独立对话较少，区间宽应如实呈现。
- 人工盲审组间分歧题，并按预先固定比例抽查共同通过/共同失败题；标准更改不能只作用于某一组。

产物：固定 reader 的最终质量与成本报告。

### 阶段 4：次级产品验证

1. 可选 PersonaMem v1 保留集 70 题，H/F 各 3 次，追加 420 次回答生成；独立报告偏好利用，按 persona 聚类。
2. 预先冻结一组约 20 题的真实 Agent 集成子集，允许相同的记忆工具和最多 12 步，H/F 相同预算。记录首次检索、累计检索和最终回答，不能用多轮结果覆盖固定 reader 主成绩。
3. remember/forget 与错误关联负例保持独立专项，不能混入原始公开 benchmark 分数。

次级验证不应阻止主报告如实交付。缺预算或条件则记 NOT RUN。

## 8. 归因记录与代码注意事项

现有 [Recall 结构](/Users/namei/idea/akashic/plugins/akasha/recalls.py:50) 已有 lane、sources、basin_ids 和 presented_message_ids，可作为证据映射基础。

但 completion 内包含 basin_direct、basin_completion、sharp_completion 与 relative_tail。只有 lane=completion 不能证明是图桥接；来源标签也不单独构成因果证据，必须结合 C/T 消融。参见 [来源标签](/Users/namei/idea/akashic/plugins/akasha/domain/readout.py:736)。

[MemoryCycle.retrieve](/Users/namei/idea/akashic/plugins/akasha/application/cycle.py:128) 支持 capture_paths / include_completion。capture_paths 不能自动覆盖所有内部盆地扩散路径；需要完整路径时在评测诊断模式补充插桩，不编造缺失轨迹。查询不改变已发布图的合同必须继续测试。

建议实验目录 `eval/association/` 提供 manifest、split、baseline、retrieval、reader、scoring 和 reporting 入口。复用现有 [memory_ablation.py](/Users/namei/idea/akashic-worktrees/benchmark-readiness/eval/memory_ablation.py)，不要在日常默认模式中加入评测旁路。

每条结果至少包含：dataset/revision、case_id、conversation/persona_id、arm、repeat、源码/制品/配置 hash、历史截止、图版本、模型身份、预算、gold evidence IDs、候选 IDs、呈现 IDs、来源标签、答案、判分、分段时间、token/工具用量、错误与尝试身份。

原始 gold 与运行输入分开存放。结果只保存在新建实验目录，旧结果不可覆盖；不改日常服务、插件缓存或真实用户数据。

## 9. 如何解释结果

- F 的证据召回提高、回答没有提高：说明提供了更多标注证据，但下游利用价值尚未证明。
- F 的回答提高、证据指标未提高：分析排序、上下文或模型差异；不能直接归因于图找回了新证据。
- F 优于 H，C/T 退化且负例表现未恶化：为关联机制贡献提供更强支持，仍限于固定数据与条件。
- F/C 差异存在但 F 不优于 H：说明内部补全有用，但不能宣称优于混合检索。
- 增益区间跨零：报告尚未证明稳定优势，不能为了显著性不断加题或选择最好一次运行。
- 简单题或拒答明显变差：报告收益与代价，不宣称全面提升。
- 只在合成图上成立：称为机制验证，不写成真实对话或公开 benchmark 效果。

不预设“必须提升 20%”等目标。简历只引用冻结评测中实际支持的结论，并注明数据集版本、子集、比较对象和百分点/百分比口径。

## 10. 交付物
