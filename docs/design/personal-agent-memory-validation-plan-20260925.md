## 1. 已有证据与本轮边界

已经完成的结果必须保留，不能因为结果不利而删除或改名：

| 实验 | H | F | 解释 |
|---|---:|---:|---|
| LongMemEval 100 题语义正确率 | 84.33% | 85.33% | 整体差值区间跨零，尚未证明稳定优势 |
| 其中跨会话 15 题 | 46.67% | 60.00% | 探索性信号；差值区间仍跨零 |
| 其中时间推理 15 题 | 80.00% | 86.67% | 探索性信号；差值区间仍跨零 |
| LoCoMo 100 道可回答题官方 F1（0–100） | 46.17 | 33.50 | 当前文本适配下 F 较低 |
| LoCoMo 标注证据召回率 | 78.47% | 54.37% | 需要定位候选选择和读出阶段的损失 |

LoCoMo 的实际证据量也不同：H 平均 11,962.7 字符、60.3 条原始消息；F 平均 3,807.0 字符、18.6 条。两组共享的是上限，不是相同实际输入长度。已有 3,000 / 6,000 / 12,000 字符检索诊断中，H 的召回均高于 F，不能把差距全部归因于上限使用率。

已有试验覆盖了历史摄入时的图学习和固定读出。`MemoryCycle.commit(turn, None)` 会在内部重新 retrieve，不能误认为传入 None 就没有运行学习。已有 QA 阶段保持只读，尚未单独验证自然语言纠正如何经完整 Agent 链路改变后续记忆。

已看过结果的 LoCoMo 120 题和 LongMemEval 100 题可以用于诊断和回归，但不能在基于这些结果调参后，继续称为未见测试集。

## 2. 固定条件

| 条件 | 约定 |
|---|---|
| 阅读模型与裁判 | gpt-5.6-sol / max，核对实际绑定与调用记录 |
| Embedding | text-embedding-v4 / 1024；共同使用有内容与空间身份校验的缓存 |
| 主证据上限 | 12,000 字符，包含证据 ID、说话人与时间等渲染开销 |
| 资源记录 | 实际输入/输出/思考 token、调用次数、延迟、失败和用量覆盖率 |
| 单次调用超时 | 300 秒 |
| 输出长度 | 请求参数和实际输出分别记录；当前 Codex 驱动不转发 max_output_tokens，不能称为强制上限 |
| 并发 | 主试验单 worker，H/F 按题轮换先后顺序 |
| 重复 | 开发 pilot 每组一次；正式每组每题三次，先按题平均 |
| 读取 | 同一历史、当前问题、最近上下文和公开反馈信息；不将评价标签送给检索器或 reader |
| 基线能力 | 动态更新试验中，H 同样具备约定的更新、失效及删除过滤能力 |
| 版本 | 固定数据 revision/hash、源码、插件制品、依赖、提示词、抽样 ID 与随机种子 |

## 3. 阶段 A：诊断现有召回问题

### 工作

1. 复用既有语料、向量、查询及排序结果；已有预算曲线直接复用，不重复请求模型。
2. 为 F 记录三个边界：线索/种子阶段、原生候选读出阶段、预算内最终呈现阶段；H 记录 dense、BM25、RRF 与最终呈现阶段。
3. 标出每条标注证据在哪一步丢失：未成为候选、候选排名靠后、原生阈值/条数裁切、字符预算裁切，或源标注问题。
4. 分组检查明确线索、跨会话、时间与短消息场景，核对消息粒度、说话人和时间适配。不能把 LoCoMo 两位参与者直接当作 user/assistant 配对。
5. 同时检查 F 增益、F 退化、双方通过和双方失败的例子。诊断不得改写原始答案或评分。

### 产物与验收

- `retrieval-loss-ledger.jsonl`：逐题逐阶段的候选/证据去向和排除原因。
- `diagnosis.md`：已证实问题、待检验假设、建议的最小修复或后续消融。
- 增加诊断后，原有召回集合与排序必须逐条一致；查询前后持久逻辑状态一致。
- 本阶段新增回答模型调用为 0。若发现真正的适配器错误，先记录受影响结果与协议版本，再修复和做回归；不把算法得分较低当作运行错误。

## 4. 阶段 B：PersonaMem-v2，验证个人偏好理解

### 数据

- 固定 PersonaMem-v2 的官方纯文本版本和 32k 历史。
- 开发从 `benchmark/text/val.csv` 选 10 个 persona、每人最多 4 题，目标 40 题。
- 正式从 `benchmark/text/benchmark.csv` 选 30 个不同 persona、每人最多 4 题，目标 120 题。
- 遵循官方 persona 隔离划分，并实际校验 persona ID 与历史内容摘要不跨开发/测试。
- 覆盖隐式偏好、更新后的偏好、他人信息与用户自身信息的区别，以及不应使用的信息。分组可以重叠，报告真实分母；按元数据分层，不按模型结果选题。
- 某用户或分组不足时记录实际样本量，不依据表现反复换用户补齐。
- pilot 固定 12 道开发题，覆盖至少 6 个 persona，避免全部取自同一个用户。

### 适配验收

- 仅历史对话进入记忆，保留 user/assistant 顺序和完整交互边界。
- `raw_persona`、`preference`、`prev_pref`、正确答案和 `related_conversation_snippet` 等标注不得作为检索输入。
- 如官方任务使用选项，给两组同一套按固定种子排列的选项，隐藏正确选项标签；不得只把正确答案相关词用于检索。
- 有可靠原始时间就保留；没有真实时间时只保留顺序，并记录内部顺序时钟的适配，不能据此宣称测出了真实时间遗忘能力。
- 对应证据片段只有在能唯一映射到历史时才用于证据指标；歧义映射单列，不强行生成 gold IDs。
- 先确认官方评分入口及输出协议，固定脚本版本和示例测试后再开始模型调用。

### 指标

- 主要：官方个性化任务得分/选择正确率，依实际官方任务协议明确命名。
- 分项：隐式偏好、偏好更新、他人信息误用和应忽略信息的处理。
- 辅助：有效标注的证据覆盖、实际 token 与延迟。
- 按 persona 聚类计算配对区间，不能将同一用户的多个问题当作完全独立用户。

这是“记忆 + 固定阅读器”的个人化能力试验，不能将全部偏好推断能力归因于图结构。

## 5. 阶段 C：LongMemEval，新题确认探索性信号

### 数据与曝光审计

- 沿用 cleaned-S 的固定上游版本和 provided-history 口径，保留原始日期，不重新施加分钟级截断。
- 当前 500 题减去既有 30 道开发题和 100 道测试题后，候选池为 370 题。这个数字尚未扣除早期零散 smoke 的题，不能直接称为 370 道未见题。
- 遍历旧实验报告、题号、人工核查与回归记录，建立 `exposure-ledger.json`；排除任何已用于设计/评测的题。
- 检查候选题与开发集之间的相关来源会话重叠；若不能保证来源独立，明确标为“未见问题”而不是“未见用户/经历”。
- 预注册目标 120 题：跨会话 40、时间推理 30、知识更新 10、用户单轮事实 10、助手单轮事实 10、偏好 10、拒答 10。不足时如实减少，不根据得分补抽。
- 各分组结果全部报告；这是重点能力分层采样，不是原始 500 题自然分布的全量成绩。
- 使用旧开发集固定 12 题做环境校准；原有 100 题结果作为历史对照单列。

### 指标与判断

- 主要确认目标：跨会话和时间推理的配对正确率差值。
- 同时报告全体分层样本、其他题型的回退、证据覆盖、拒答和资源消耗。
- 两个主要分组都必须披露；若只出现单组信号，应按分组报告，并明确多重比较/探索性边界。
- 置信区间包含零时写“证据不足”；不为了得到显著结果连续追加题。
- S/M 版本可能共享题目，更换历史长度不构成一批全新的独立问题。

## 6. 第二批：Memora weekly，验证更新和遗忘

### 范围

- 首轮只使用 weekly：官方有 10 个 persona，每个 15 道评价问题。
- 按固定种子选择 2 个 persona 开发、8 个 persona 测试，对应 30 道开发题、120 道正式题。
- 开发 pilot 12 题覆盖两个 persona 和 remembering / reasoning / recommending 三种任务。
- monthly / quarterly 不包含在本轮调用范围；它们与 weekly 共用 persona，不能当作新的独立用户。

### 输入与公平条件

1. 按原始 session/date 顺序摄入对话；读取在更新之前，完成交互才进入记忆。
2. `memory_evidence`、`forgetting_evidence`、评价问题及期望 yes/no 标签只用于评分。
3. 不根据 `share_memory` 或隐藏标注只挑“重要”发言入库；两组获得同样的完整可见历史。
4. 只有从可见对话或官方明确允许的输入事件得到的纠正/遗忘指令，才能触发更新。禁止直接把评分标签转成 Akasha 的 forget 目标。
5. 两组使用同一条已冻结的指令解释规则；H 同样支持更新和失效过滤。解析错误、目标定位失败与检索错误分别记录。
6. 若无法忠实接入自然语言反馈，先报告适配缺口，完成接口功能测试；不借助 gold 标签伪造一条成功反馈链路。
7. 此处遗忘指不再用失效内容作答，不据此声称原始消息已物理删除。

### 指标

- 按固定官方实现计算 FAMA，并分别报告 memory presence 与 forgetting absence。
- 没有 forgetting 子项的问题，不应被自动记为“遗忘成功”。
- 补充过时信息复现率、有效信息误抑制率以及更新前后行为变化；只有存在合法成对查询/事件时计算变化指标。
- 按 persona 聚类；只有 8 个测试 persona，结论限定于这批样本。

## 7. 可选：情景联想机制测试

默认先只测检索，不增加回答模型调用。

- 20 个开发故事、40 个独立测试故事，每个故事 3 个查询，目标 120 道测试查询。
- 每个故事包含多次交互、可识别的事件连接，以及同词不同事件的干扰。
- 三类查询：完整线索、部分/间接线索、带相似事件干扰的线索。
- 例如用保存获奖通知的红色信封作为线索，寻找更早的比赛及后续安排；故事中必须真实提供连接依据。
- 两组获得相同近期上下文；不能仅向 Akasha 提供用于消歧的活动 burst 内容。
- 开发/测试按故事模板、主题和实体组合分离；查询与标签在运行前审阅并冻结，不能用 Akasha 的输出反推标准答案。
- 主要指标：关键事件覆盖率、完整情景恢复率、无关情景混入率、证据量和检索耗时。
- 单列为合成机制测试，不能与公开数据集平均，也不能据此宣称通用记忆系统领先。

## 8. 执行批次、用量与停止条件

| 批次 | 模型回答次数 | 前提 |
|---|---:|---|
| 现有问题诊断 | 0 | 复用冻结数据及向量 |
| PersonaMem-v2 pilot | 12 × 2 = 24 | 数据及官方评分器验收 |
| PersonaMem-v2 正式 | 120 × 2 × 3 = 720 | pilot 链路有效，配置及题号冻结 |
| LongMemEval pilot | 12 × 2 = 24 | 新环境/协议校准 |
| LongMemEval 新题正式 | 120 × 2 × 3 = 720 | 曝光审计、抽样及分组目标冻结 |
| Memora pilot，第二批 | 12 × 2 = 24 | 更新/遗忘输入语义对齐 |
| Memora 正式，第二批 | 120 × 2 × 3 = 720 | pilot 链路有效，反馈处理冻结 |
| 合成机制集，仅检索 | 0 | 数据和标签冻结；embedding 调用另计 |

第一批最多 1,488 次回答生成；Memora 第二批另加 744 次。裁判、embedding 和既定传输重试另计，Memora 的 rubric 子项数也需纳入裁判用量核算。每批先用 pilot 测得真实 token 和耗时，再估算剩余消耗；不预先承诺固定费用或工期。

停止条件只针对无效运行和资源问题：数据映射/模态/时间协议不清、模型身份或 embedding 空间变化、持续认证/配额错误、评分器无法判定。失败记录保留。Akasha 分数较低不是删题、改分或改变停止时点的理由；配置有效的正式批次按预注册范围完成。

## 9. 结论与交付

- 场景优势：预注册的主要指标有正向配对差值，且区间支持该方向；同时披露所有回退和资源开销。
- 探索性信号：点估计较好但区间跨零，或只在事后挑出的分组出现差异。
- 工程可靠性：确定性重放、异常恢复和原始事实保全用独立机制测试证明，不用问答成绩替代。
- 单纯 token 下降只能称为输入减少；没有事前非劣界限与合适统计设计时，不声称“质量不下降”。

交付固定数据清单、曝光清单、配置与版本、逐题检索/回答/评分、阶段错误、配对统计、资源账和中文报告。结论分别回答：哪些个人 Agent 场景值得使用 Akasha、哪些场景 Hybrid 更合适、哪些机制需要进一步验证。
