# 0128 · Codex 回合通知经本机 Gateway 写入独立会话

- 状态：accepted
- 日期：2026-10-23
- 关联：OUT-001、STA-001～STA-003、CAP-002；延续 [0126](0126-task-destination-sessions.md) 的固定会话意图

## 决定与理由

用户的桌面 Codex 在 Windows 运行，Akashic 在同机 WSL 运行。Codex 的 Stop Hook
经 wsl.exe 将有界事件保存到 WSL 发件箱；转发器经现有私有 Gateway Unix socket
提交给 codex_notifications。插件以固定身份接纳「Codex 动态」会话，沿既有
Ledger / Delivery 协议追加 assistant Output。Wake、模型调用和新网络端口不参与。

┌─────────────────────┐   ┌──────────────────────┐   ┌─────────────────────┐
│ Windows Codex Hook  │──▶│ WSL 本地持久发件箱   │──▶│ Gateway / 通知插件  │
└─────────────────────┘   └──────────────────────┘   └──────────┬──────────┘
                                                      ┌───────▼─────────┐
                                                      │ Codex 动态会话  │
                                                      └─────────────────┘

Stop 只表示本轮停止，不证明整个任务完成、测试成功或没有待确认事项。正文保留这一
含义；不读取 Codex 内部数据库、transcript 或认证文件。通知只接收会话、回合、目录、
时间和最多 6000 字符的最终回复摘要，截断显式标记。既有 notify 与其他 Hook 保留。

此来源只有一个固定 Akashic 目标，不提供任意会话或外部渠道选路。接纳直接依赖
Ledger 的窄端口，不为了安装通知而升级旧实例的 Conversation、Core 或其他插件。
会话标题仅首次设置；删除后的会话不自动复活，之后事件保留在发件箱等待处理。

## 状态、失败与恢复

- 发件箱由桥接程序拥有。事件首次插入后不改正文，ACK 与重试诊断可以更新；当前
  没有自动清理协议。桥接身份和接收端绑定在创建后保持固定。
- 接收插件通过 Ledger OwnerState 以桥接身份、Codex 会话、回合和事件类型去重。
  原事件与目标只写一次；相同身份携带不同正文明确拒绝。没有迁移或删除旧消息。
- 消息与 Delivery 初始选择原子提交。返回 committed 表示 Akashic 会话已保存；
  即时提醒的真实状态另列。断线、回执丢失和重启重投沿用同一消息与原发送绑定。
- 新事件接纳与消息提交之间中断时，发件箱重投补齐；停用插件只停止接收，保留已
  保存消息、事件和发件箱。回退软件不回退已经新增的通知。

## 验证

隔离真实插件栈和 Gateway/SDK 验证并发重投、冲突拒绝、重启、手动改名、会话删除
和旧消息完整保留；通知不触发模型。Windows/WSL Hook 与实际部署另做设备验证。
