# 0145 · 原生 WSL 只回退证据完整的启动失败

- 状态：accepted
- 日期：2026-11-21
- 关联条款：RUN-004、MIG-001、STA-001
- 部分 supersedes：[0074](0074-deployment-policy-belongs-to-operator.md) 第 5 项对原生 WSL 的限制

原生 WSL 自部署完整发布后，若候选启动或就绪验收失败，宿主可在同一个发布请求中尝试恢复旧版。预检和实际发布回执须同时证明没有待执行迁移、没有外置目标。当前完整插件组合、最后一次选择提交和启动指针须与本次发布对应，外置输入须与切换前完全相同。

候选已退出、旧制品仍可用且插件操作均已结算时，宿主持有启动锁和离线发布锁，由选择 owner 以候选 Root 为前提，重新提交此前完整的有序插件输入，再启动并验收旧版。systemd 已排定重试时，启动器在同一把启动锁内读取已切回的指针。旧输入保留在本次 worker 内存。直接重新提交已有输入可避免重跑安装器和迁移，也不会回写业务数据、配置、会话或外部效果。

发布结果不明、条件不满足、候选仍占用状态或 worker 中断时，由部署者按现有回执处理。自动恢复成功仍记录原更新失败和旧版就绪，恢复失败保留两段错误。人工 `resume` 和 `rollback` 继续使用原有证据与授权。

隔离验收覆盖旧版恢复后可继续聊天，历史消息和外置输入一致，以及迁移、外置更新或组合不匹配时保留候选现场。
