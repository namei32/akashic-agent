## 背景

用户希望 Agent 结合长期记忆主动搭话。现有 Drift 定时机会进入 Wake 的分享或跳过
判断，但 Wake 内部会话没有真实用户 Input，Default Memory 不会据此自动召回。
Wake 的已送达历史和 EventMail Context 现可跨会话读取，不能直接假定都适合某个
项目范围。结构化记忆的旧召回回执还可能包含后来被遗忘或替换的事实。

## 决定

1. 独立启用记忆增强主动交流，并明确授权一个可证明为私人的精确投递目标；
   首版的来源和目标使用同一个会话。默认关闭，沿既有策略按来源会话路由记忆。
2. Default Memory 提供范围内召回、真正呈现项和短有效性保护；Wake 使用同一次
   scoped Drift 判断给出 none 或 chat，不再添加独立的模型价值判断循环。
3. 模型阶段接纳、目标会话发布和渠道首次发送分别验证机会、暂停、目标授权和
   事实有效性。记忆 owner 与 Drift owner 通过固定锁顺序保护短提交，网络等待不持锁。
4. 依据实际材料 owner 限定近期对话、已送达历史和其他 Context 的范围；
   无法确认的内容不混入目标范围。成功只由真实送达回执确认，内部工作不自学为用户事实。

已有对话、召回回执、内部消息、记忆来源和已开始的外部效果保持各自的原 owner
与恢复合同；逻辑遗忘不等于物理删除原文。具体接口、故障和阶段见
[Drift 与 Default Memory](../design/drift-default-memory.md)。

## 理由与替代

- 以来源会话而非 wake 内部会话路由，可以使用现有 global、isolated 和 recall
  策略；不复制项目权限或让内部默认 scope 意外扩大读取范围。
- 已有 Wake 拥有最终 share/skip 决定。另起 Drift 模型再让 Wake 判断会增加费用、
  恢复状态及冲突决策；未来需要 work 规划时再单独设计，不把它塞进本阶段。
- 固定会话可审查且可恢复。自动选择最近会话还缺少跨渠道身份、受众和项目授权事实，
  也可能因助手自己的消息而错误更新“最近”。
- 单次查询后只检查 active 状态存在与遗忘并发的窗口；只保护渠道发送则可能已经
  在目标会话发布正文。因而需要覆盖实际提交的短保护，并分别处理已发生的效果。
- 首版拒绝受众未知的目标可能限制可用渠道；当渠道能提供可靠身份、受众及授权
  协议时，可重新评估多目标或跨会话使用。

以隔离实例验证范围、用户证据、遗忘竞争、取消、换代、重启及真实送达。
