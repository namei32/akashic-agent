# 0126 · 周期任务绑定固定的可见会话

- 状态：accepted
- 日期：2026-10-22
- 关联：SCH-003、SES-005、MEM-001；扩展 [0125](0125-scheduler-runs-in-its-session.md) 的创建目标规则

## 背景和决定

用户要求每日战绩等任务进入专用会话，与 Wake 主动联系分开。每次触发新建聊天会割裂历史，
只改显示分组则仍会混入原会话上下文。任务因此在创建时固定会话 ID，此后周期执行和恢复沿用该目标。

Scheduler 默认仍在当前会话创建，也支持选择已有可见会话或新建 Akashic 网页/手机会话。
新建身份在工具准备阶段固定，实际执行时经 Ledger 接纳；继承创建会话的记忆资格与 scope，
初始标题只在未命名时设置。失败后重试复用身份，已删除会话不自动恢复。新会话使用 Akashic
渠道；外部 IM 聊天的创建须由对应渠道自己提供，不能拼造外部房间号。

Scheduler 发布 `scheduler.task-sessions.v1`，供周期报告复用目标查询与接纳；不增加 Core 能力，
不在 Wake 中按插件名称分流。选择已有会话时固定其投递路线，候选只包括可见且未删除的会话。
任务内的模型与历史范围继续遵守 0125，自动来源不会变成用户发言。

## 状态与恢复

新任务仍写入 schedules.json v3 的既有 session_id/channel/chat_id 字段；不改旧任务或旧触发。
新建会话与初始标题是新增持久状态，不删除或重写旧消息。两个 owner 的提交之间失败可留下空的
专用会话，重试继续接纳同一身份；没有自动清理协议。任务创建回执和任务列表都展示目标会话 ID。

## 验证

通过隔离插件栈、真实渠道接纳、工具调用、调度和投递验证新建、复用已有及无效目标；
周期触发复用同一个目标，创建会话不出现任务报告，重开任务存储仍保留目标与触发，已有消息内容不变。
