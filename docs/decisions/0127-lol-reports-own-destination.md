# 0127 · LoL 日报直接投递到固定会话

- 状态：accepted
- 日期：2026-10-22
- 关联：[0126](0126-task-destination-sessions.md)、PRO-001～PRO-004、STA-002

## 决定与理由

每日报告是用户明确订阅的周期输出，默认使用可追问的「英雄联盟战绩」会话，也可在设置中选择已有会话。
LoL 继续拥有采集、日报时间和报告生成；Conversation 提供会话选择与接纳，Delivery 保存真实发送回执。
这次不搬迁 LoL 的时钟，也不让它依赖 Scheduler 启用；新报告不经过 Wake 的 Alert 流程。

报告首次 claim 时，在同一个 LoL SQLite 事务中增加报告事实与 `metadata` 中的
`report-destination:<报告身份>`。目标只写一次；配置变化只影响新报告。Ledger 中的消息 ID
由插件身份与报告身份确定，正文与发送选择经 Delivery 原子发布，恢复复用原消息、地址和 sender binding。
自动报告来源为 `lol_tracker`，不伪装成用户输入；用户之后的追问沿普通对话学习规则处理。

## 既有状态与失败

旧报告没有 destination 记录，继续通过原 EventMail Alert 完成提交或核对回执；已提交的旧报告不重发。
新报告只有 Delivery 确认 delivered 才设置 published；拒绝和失败保存回执，不能显示为已送达。
显式重试只重新启用 Delivery 允许重试的原效果，不换目标或绕过未知结果核对。会话删除不会自动复活或改投 Wake。
采集事实、旧消息、报告正文与回执均保留；不存在自动删除或历史搬迁协议。既有表结构不变，
destination 是原 metadata 表中的新增记录；receipt 仍保存接纳方回执，UI 根据 destination 区分旧提交与新送达。

已产生新协议的未结报告后，不能直接回退到会忽略 destination 的旧版本：先停用报告生成并核对、结算
未结投递，再决定回退；不能靠删除回执恢复旧行为。

## 验证

隔离插件栈验证专用会话复用、真实渠道追问、旧 Alert 丢失生产者 ACK 的恢复、接收端拒绝后显式重试、
发送完成但生产者 ACK 未写入时重启，以及改选后新旧报告各自的目标。配置读写走真实配置 owner；
所有外部发送使用隔离接收端，不调用真实游戏客户端、模型或聊天账号。
