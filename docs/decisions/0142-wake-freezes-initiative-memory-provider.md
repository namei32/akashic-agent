# 0142 · Wake 固定主动记忆提供者，Akasha 保护实际呈现出处

- 状态：implemented for review
- 日期：2026-11-13
- 细化：[0130](0130-drift-recalls-memory-in-source-scope.md)

## 背景与决定

切换主记忆到 Akasha 时，现有 Drift 不能继续依赖只有 Default Memory 才提供的服务，
也不能把旧事实快照当成新图上的结果。两者保留各自公共服务身份；Wake 配置选择
`memory_provider`，每条请求固定该选择。无该字段的旧请求仍解释为 Default Memory，
提供者缺席明确不可用，不在两者之间自动回退。

Akasha 仅在主记忆模式提供范围内 admit、prepare、guard。接纳保存精确请求摘要，
实际查询冻结预算内的正文、消息引用、结束消息和原始出处摘要；重试读原快照。
查询向量在图锁外调用模型。发布和首次发送前的短 guard 不调用模型、不推进学习，
持有图访问锁与 provider lease，核对当前路由、可用来源和原节点，拒绝已遗忘、
被排除或不再属于当前图的材料。原始消息、Default Memory 和全部回执不减少。

## 理由、代价与验证

独立服务避免 Akasha 冒用 Default Memory 的 owner 合同；请求固定选择避免换代时
重新解释旧材料。复用现有 Wake 判断及目标授权、暂停和送达保护，不新增主动判断循环。
学习更新只有改变呈现出处或遗忘状态才使快照失效，其他新经历不导致无关发送饥饿。
来源会话删除与提交之间的既有限制仍遵循 0130，不宣称跨 owner 全局事务。

真实插件、HTTP 模型和接收端场景分别运行两种提供者，并检查撤销、遗忘竞争、暂停恢复、
重复发送、模型跳过/失败、隔离范围和拒绝召回。回退时保留新请求与快照；有待处理请求
时须先结算或使用兼容服务版本，不能恢复旧消息库来制造回滚。
